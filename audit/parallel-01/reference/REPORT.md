# Complete known-solution reference audit (B)

**Result:** nine complete community reference groups (2,979 runes) pass exact rune-index comparison using small independent cipher implementations. They cover the rune text associated with all 17 rune-bearing solved physical pages: 15 LP1 pages and LP2 images 56/57. LP1 00/02 are Latin title pages, inventoried without cipher tests. This is complete group-level reference coverage, **not an independently verified image transcription or a certified physical-page boundary map**.

The inherited seven-script suite still returns 7/7 PASS, but only three printed outputs equal the complete corresponding reference group. A fourth matches its selected 742-rune subsection but omits the 38-rune instruction. Three keyed outputs lose genuine plaintext F runes; WELCOME additionally chooses an incorrect interruption path. These are substantive failures hidden by keyword checks.

## Source-backed expected answers and independence

The complete expected rune texts are downloaded, pre-existing `pages/solved_*.txt` files from [relikd/LiberPrayground](https://github.com/relikd/LiberPrayground/tree/main/pages). Corresponding ciphertext files and the [documented solver configurations](https://github.com/relikd/LiberPrayground/blob/main/solver.py) are preserved in `sources/`; `retrieval.json` records URLs, 2026-09-16 retrieval times, bytes and SHA-256. These are not answers generated by the code tested here, nor copies of this repository's reproduction template. They are externally authored reference outputs, and may themselves have been generated by relikd's solver. Thus they independently check our implementation, but do not constitute two independently transcribed image witnesses. `reference.py` imports no inherited or downloaded code, scorer, cipher, mapping, prime generator or parser.

The alphabet order is explicitly frozen in `reference.py`; its 29 tokens agree with A's independently checked dataset. Expected answers use runes directly, avoiding ambiguous Latin-to-rune conversions. English-looking text is display only. Orthographic forms such as WIDSOM, BEL EI UE spelling, IA for IO, and omitted I before NG are not silently corrected. The reference plaintext has exactly one rune at each ciphertext-rune position, including F interrupters. The operation at those positions is **emit F and do not consume key**, rather than delete F. Keystream state continues across each grouped source; headers consume key. No automatic key or interruption search is used.

The two attempted direct root downloads `Rune.py` and `RuneSolver.py` returned 404 and are recorded as errors; they were not needed or used. An intermediate log-portability edit of `run.py` failed before any child launch with NameError (Path versus pathlib.Path); fixed and final runner repeated. Initial source-inventory shell typo (unmatched parenthesis) exited 1 and was corrected before tests. Initial `compare.py` imported the executable `check.py`, whose exit prevented comparison; `logs/runs-initial.json` preserves that misleading initial exit record. This audit-code defect was fixed by moving inert configuration to `fixtures.py`, then the complete runner was repeated. Final comparison artifacts are present and checked. The initial raw fetch stdout is saved.

## Discrepancies

All indices below are zero-based **rune** positions within the named group/output, not Latin-character offsets.

* **Inherited WELCOME:** first difference48: expected F in `END OF ALL`, actual A after deleting F. Printed output is387 runes from394 input, versus515 in the full group. The printed `SUMMOSTUR` also differs from source `SUFFERNG YOUR`: recovered interruption occurrences differ from the documented source path. This is decoder/model error plus incomplete group selection, not an input difference: joining local sections03+04 exactly matches the515-rune external ciphertext.
* **Inherited circumference:** first difference49, expected F in `VOICE OF THE`; actual TH. It emits317 of319 plaintext runes. Correct source interruption positions are the same, but deleting the F is wrong.
* **Inherited An End:** first difference56, expected F in `DUTY OF EUERY`; actual E. It emits84 of85 plaintext runes. Its corrected tail is still missing an F.
* **Inherited koan:** correct complete742-rune selected subsection, then stops at rune742; full group has780 because the instruction on09.jpg is absent from the script's selection. This is coverage omission, not arithmetic failure.
* **Local loss-of-divinity input:** first difference126, local lacks O in FOLLOWNG;754 local versus755 external. This is an input/reference transcription dispute; no cipher is involved. No image adjudication was attempted, and the local source was not changed.
* **Local scream314 Parable:** first difference80, E in DIVINITE versus external Y in DIVINITY. A's input and the inherited standalone Parable script use the other source and agree with Y. A subsequently inspected the original image and reports Y at this site (see `../inputs/crops/p57-site80-detail.jpg`, bbox [890,1710,1030,1880]); this supports an error in the local scream314 transcription. This is input/reference, not cipher arithmetic.
* The standalone warning, wisdom and Parable scripts match complete reference groups exactly.

`inherited_comparison.py` reconstructs rune arrays from the actual printed methods and interruption sets, and asserts their transliterations equal every printed inherited output. This avoids pretending a lossy Latin string can be uniquely inverted into runes. Complete arrays are then compared to the external expected fixture. It does not alter or monkeypatch inherited code.
