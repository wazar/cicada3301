# Review16 — source-derived classic JSteg v4

Scoped review passes. Worker-P's final P11 output and independent checks establish that both authorized originals begin with a width31, length2,147,483,647 header under this exact extraction rule. Available payload capacity is only89,296 and85,898 bytes. These are incomplete declared payloads, not candidate messages. No forced extraction, alternate header, offset or key search was performed.

This report and authored tests do not reproduce substantial source.

The source extractor visits reconstructed quantized DC, followed by nonzero AC coefficients in decoded zigzag order. Traversal follows MCU order and component/block order, including coded dummy blocks if present. The predicate excludes exactly0 and+1. Negative1 contributes bit1. DC differences and dequantized DC are not substitutes. Both authorized actual images have no dummy blocks; prior Review15 validated a synthetic dummy-block branch, but it is not evidence that omitted dummy values can be reconstructed from cropped coefficient arrays.

Header interpretation is five MSB-first width bits, followed by that many MSB-first length bits, then payload bytes. README and actual injector differ: README describes occasional extra leadingzero, but source has no randomization and intended32-bit getrepwidth returns minimal width for sizes>=2. Size1 reaches a shift by32, undefined in the original C. A named repair to produce width1 is an intended-format emulation, not proof of every historical compiled binary's behavior. Native LP64 does not fix the code: hard-coded33 minus a64-bit shift wraps when assigned to the unsignedshort width. Empty input is consumed by refresh before any header bit is returned. A zero-length header is therefore not automatically a legitimate empty source encoding.

The sink's zero-length behavior was checked rather than replaced with modern semantics: it processes data bits, reports a partial-byte error internally while fileindex remains0, never closes successfully, and can flush later1024-byte chunks. The independent fixtures confirm these open-state and flush behaviors. Positive lengths with a nonminimal width can be read by the sink, even though that is not the minimal-width injector's output. Reader acceptance, README compatibility and injector compatibility are separately recorded.
